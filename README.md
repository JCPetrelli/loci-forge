# loci-forge

Build memory palaces (method of loci) in 3D with Blender, the Blender MCP server and Claude.

The method of loci is an old memory technique. You walk through a place you know, in your head, and leave one vivid image at each station along the way. To recall the material you walk the route again. loci-forge makes those places real: you describe a topic, Claude plans the route and the images, and Blender MCP builds the palace so you can walk through it and render it.

## How it works

1. **Topic.** Write down the notions you want to memorize in `topics/`, for example a list, a chapter outline or a set of definitions.
2. **Plan.** Claude turns the topic into an ordered route of loci (rooms, stations, objects) and gives each notion a vivid, unusual image.
3. **Build.** Through the Blender MCP server, Claude builds the palace: architecture, props, lighting, labels and a camera path along the route.
4. **Walk.** Render a fly-through or explore the scene in Blender to rehearse the route.

## Quick start: walk through a palace

`loci_base.blend` is the starting file. It holds a small sandbox (a room with a doorway, stairs, a terrace, a ramp and five numbered pedestals as sample loci), a simple mannequin, and the **Loci Walker** add-on, which loads itself from `scripts/` when the file opens.

1. Clone the repo and open `loci_base.blend` (or run `just run`). When Blender asks, click **Allow Execution**: the file's startup script loads the walker.
2. In the 3D viewport, open the sidebar (`N`), go to the **Loci** tab and press **Walk**.

| Key | Action |
|-----|--------|
| `W A S D` / arrows | move |
| mouse | look |
| `Shift` | run |
| `Space` | jump |
| `V` | switch between first and third person |
| mouse wheel | third-person camera distance |
| `Esc` | exit and restore the viewport |

The walker collides with every visible mesh in the scene, climbs steps up to 35 cm and handles ramps. To make an object walk-through (glass, fog, decorations), give it a custom property `loci_nocollide = 1`. To use the walker in another .blend, either install the add-on (`just package`, then *Preferences > Add-ons > Install from Disk*) or save the file in this repo's root and add `scripts/loci_boot.py` as a text block with *Register* ticked.

**Place Player at 3D Cursor** moves the mannequin to where you want to start. Movement and camera settings live in the same panel.

To rebuild the base file from code: `just build`.

## Sample palace: the Archive

`loci_start.blend` is a larger example: an abandoned archive hall, 18 × 15 m and 9 m high, with a tall bookcase lit through a hole in the roof. Its furnishing is generated by `palaces/archive/furnish.py` and laid out as a route of distinct stations:

1. the entrance, with a clock stopped at 3:47
2. a brass armillary sphere on a round rug
3. a long reading table with green banker's lamps, by the windows
4. a card catalogue with drawers pulled out and index cards on the floor
5. two paintings between the windows
6. three glass display cases (an hourglass, a marble bust, glowing crystals) in the open hall
7. a staircase up to a gallery of bookshelves
8. a telescope aimed at the hole in the roof, a large globe, and an armchair by candlelight
9. an upright piano with an open score
10. an arched green door at the end of the gallery, the way on to the next environment

Its image textures (worn concrete, plaster, leather, wood and metal) come from [Poly Haven](https://polyhaven.com/) and are not in the repository. They are CC0, free for any use. Download them once before opening `loci_start.blend`:

```sh
just textures      # or: python3 scripts/fetch_textures.py
```

This puts `diff.jpg`, `nor.jpg` and `rough.jpg` into `textures/<asset>/`, where the .blend looks for them; re-running skips files already there. Without them the .blend shows pink materials. The web player doesn't need them, since everything is baked into `palace.glb`.

The script is idempotent: it empties the `Archive_Furnishing` collection and rebuilds it, so you can edit and re-run it (from Blender's Python console, or through Blender MCP):

```python
exec(open(bpy.path.abspath("//palaces/archive/furnish.py")).read())
```

It builds with `scripts/loci_build/`, a small toolkit for palace scripts: `Batch` merges many primitives (boxes, cylinders, spheres, tori, rods), each with its own material, into one object, plus helpers for materials, lights and resettable collections.

## Play in the browser

The `web/` folder is a standalone player: open a palace in any browser, no Blender needed. It uses three.js from a CDN, has no build step, and works as a static site (GitHub Pages included).

```sh
just export        # bake loci_start.blend into web/assets/archive/ (about 6 min on an M3)
just run-web       # then open http://localhost:8765/?palace=archive
```

Click to start. The controls are the same as in Blender, with the mouse captured (Esc releases it).

Press `L` to show the **loci hints**: floating numbers over the places worth hanging an image on, in walking order (entrance door, armillary sphere, clockwise round the ground floor to the piano, then up the stairs and along the gallery to the arched door onward). Look-alike objects count as one locus (the three display cases, the two paintings), since images placed on similar loci get mixed up; no two loci are the same kind of thing, and none sits directly above another. Every fifth locus has a gold badge with a hand and every tenth a purple one, the checkpoints the *Rhetorica ad Herennium* (III.18) recommends for counting along the route. Numbers always face the camera; those hidden behind walls show faintly, so the whole route stays readable. They come from `palaces/<palace>/loci.json` (Blender coordinates), which `just export` copies next to the palace; edit it and copy it to `web/assets/<palace>/` to move them without re-baking.

How the export works (`scripts/export_web.py` and `scripts/loci_export/`):

1. Every visible object is converted to a plain mesh with its modifiers applied. The player, haze volumes and particle emitters are left out, and glass is split off to be drawn see-through.
2. With `--interior`, faces outside the room that face away from it are dropped. Nobody can see them from inside, and they would take a third of the texture space.
3. Objects are grouped into 4096 px atlases at an even texel density and unwrapped together. Each object's texture coordinates are first stored on its vertices, so the procedural materials don't shift when objects are joined.
4. Cycles bakes the full lighting (lamps, candles, sunlight, bounce light) into the atlases. Reflections are left out, since they would look painted on, so metals bake with their base colour.
5. Everything is exported as a Draco-compressed `palace.glb`, plus `mannequin.glb` and `palace.json` (spawn point and walker settings).

The player draws the baked atlases unlit, lights only the mannequin, and collides against the same geometry through [three-mesh-bvh](https://github.com/gkjohnson/three-mesh-bvh), with the Blender walker's physics ported one to one.

## Stack

- [Blender](https://www.blender.org/) 4.x

- [Claude Code](https://claude.com/claude-code) with Claude Opus 5.5

## Layout

```
topics/    what to memorize (Markdown)
palaces/   scripts that build and furnish palaces (archive/furnish.py)
web/       standalone browser player (three.js); assets/<palace>/ holds exports
scripts/   reusable Blender Python helpers
  loci_walker/    the walker add-on (movement, collision, camera, mannequin)
  loci_build/     toolkit for building palace furniture from code
  loci_export/    bake + glTF export for the web player
  export_web.py   the export entry point
  loci_boot.py    loader embedded in the .blend files
  build_base.py   generates loci_base.blend
```
